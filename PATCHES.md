## Patched (the carry gets these wrong for 26.3 / for this slice)

1. **`data/silentgear/horizon/item/pickaxe.json`** — the carry gives a
   `GearItem` the `minecraft:stick` template (it is not a vanilla tool class).
   The slice declares it from `minecraft:iron_pickaxe` so vanilla reads the
   iron stat block (`minecraft:tool` speed 6 + pickaxe drops, `max_damage` 250,
   `enchantable` 14, `repairable #minecraft:iron_tool_materials`), and overrides
   `item_model` and `item_name`. The stat block is the same one the runtime
   computes and the stack carries.
2. **`data/silentgear/horizon/item/pickaxe_blueprint.json`** — adds a
   `minecraft:item_name` key; the jar names blueprints with the code-driven
   `item.silentgear.blueprint = "%s Blueprint"` template.
3. **`assets/silentgear/models/item/pickaxe.json`** — the jar's model is
   `{"parent":"silentgear:item/base_gear"}`, which is `builtin/entity` with a
   custom renderer. The slice uses a `minecraft:item/generated` model of
   upstream's own `pickaxe/main_generic_hc` + `_highlight` textures. (The
   material-tinted renderer is a client-slice gap, `notes.md` gap 6.)
4. **`data/c/tags/item/rods/wooden.json`** — the jar's own file lists only
   `silentgear:netherwood_stick` (NeoForge merged vanilla sticks into the
   convention tag at runtime); the slice adds `minecraft:stick` so the
   blueprint recipe matches. 26.3 ships no `c:` tags.
5. **`assets/silentgear/lang/en_us.json`** — add
   `item.silentgear.pickaxe_blueprint = Pickaxe Blueprint`.
6. **`data/silentgear/horizon/creative_tab/gear.json`** — a `Silent Gear` tab
   with the five items (the jar's tabs are code-registered and the carry does
   not produce them).
7. **`horizon-mod.toml`** — the carry adds `namespaces = ["curios"]` (the jar
   ships curios files that are out of slice); the slice lists no extra
   namespace.
